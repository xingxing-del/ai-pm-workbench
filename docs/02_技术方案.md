# AI 产品工作台｜技术方案 v1.4

## 1. 选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 前端 | 原生 HTML / CSS / JavaScript | 不需要构建工具，克隆即可运行，代码容易讲清楚 |
| 服务端 | Node.js 内置 `http` 模块，零依赖 | 只做两件事：提供静态页面、转发模型请求 |
| 数据存储 | 浏览器 localStorage | 需求是单人使用，不需要数据库 |
| 大模型 | 兼容 OpenAI 接口的服务商 | DeepSeek、通义千问、Kimi、OpenAI 等都能接 |

## 2. 三层结构

```
浏览器
├── 规则层  rules.js   关卡准入检查、"下一步"计算。纯函数，不调用 AI
├── 引擎层  engine.js  统一推进入口、版本与过期、回退、失败回流、依据快照。纯逻辑，有单元测试
├── 建议层  ai.js      文档判断与拆解、下一步建议。模型模式 / 演示模式
└── 交互层  app.js     看板、步骤标记、决策、留痕
          store.js     数据读写（localStorage）
          files.js     多文件解析：文本直读，Word 用 mammoth，PDF 用 pdf.js（按需从 CDN 加载）
          stages.js    10 个阶段的骨架定义

server.js
├── GET  /api/config   告诉前端是否已接入模型
└── POST /api/llm      转发到 {LLM_BASE_URL}/chat/completions
```

规则层和建议层分开，是这个产品最重要的设计决定：

- 规则层决定「能不能走」，结果确定、可复现，演示时不会翻车；
- 建议层回答「建议怎么走」，可以出错，但最终由人拍板；
- 两层结果都写进决策记录，事后能追溯每次推进的依据。

## 3. 两种 AI 模式

| 模式 | 触发条件 | 说明 |
|---|---|---|
| 模型模式 | `.env` 中配置了模型 | 由大模型读取项目全貌后给出建议，要求返回 JSON |
| 演示模式 | 没有配置模型，或模型调用失败 | 由内置规则模板生成建议，界面上明确标注来源 |

模型调用失败时自动降级为演示模式，并在界面上提示原因。这本身就是一个 AI 产品的兜底设计。

## 4. 数据结构（简化）

```js
project = {
  name, iteration, currentStage, risk,
  doc: { text, type, reason, missing },
  stages: {
    1..10: {
      steps: [{ id, title, status, risk, note, output }],
      fields: { ...阶段产出 },
      gatePassed, forced, lastGate, fromDoc
    }
  },
  log: [{ t, stage, stageName, type, decision, rule, ai, reason }]
}
```

指标在第 3 阶段定义，分三类：北极星、评测（第 7 阶段检查）、护栏（第 8 阶段检查）。

## 5. 推进规则

- **统一入口**：`Engine.advance()` 是唯一的前进函数。关键节点在调用时重新执行规则；不通过就拒绝，除非显式传入强制放行。界面上的采纳建议、按规则通过、强制放行、完成本阶段都调用它。
- **会话过期**：打开关卡时记录两个签名：规则结果签名，和 AI 所依据数据的签名（相关阶段的产出、步骤、关联材料、指标、修订号）。任何一个变化，会话标记过期，只能重新检查；拍板时再比较一次。
- **统一变更入口**：所有修改都调用 `Engine.applyChange()`。它先比较前后值（相同则跳过），再按依赖关系表决定是否升修订，最后对所有已通过（非强制）的关卡做复核：不再满足规则就撤销，并连带撤销之后已通过的关卡。依赖关系表写在 `engine.js` 顶部注释里。
- **前置关卡补确认**：`Engine.confirmGate()` 在不移动当前阶段的前提下确认之前的关卡，用于未核验阶段和依据变化后的重新确认。
- **版本**：`project.ver = { std, evalset, build }`。修改标准、评测集说明或构建记录时，如果当前版本"已被使用"（关卡通过过或有结果按它录入），版本号加一，相关关卡失效。结果录入时记下所依据的版本（`evalMeta` / `grayMeta`），版本不一致即过期。
- **回退**：`Engine.back()` 重置途经关卡；从评测之后回到第 5 或第 6 阶段，视为返工，对应版本加一。
- **失败回流**：第 10 阶段的所有回流（包括问 AI 后采纳）都调用 `Engine.backflow()`：轮次加一、重置步骤与关卡、清空结果、失败案例转为新步骤；没有失败案例时须写原因。
- **依据快照**：`Engine.snapshot()` 在每次决策时保存规则明细、指标实测与阈值、版本、关联材料和 AI 完整建议。
- **异步保护**：AI 请求带会话 ID，返回时会话已变化则丢弃；补充材料返回时如果已切换项目，只保存不重绘；前端 60 秒超时覆盖请求和读取响应全过程。
- **模型上下文**：发给模型的内容包括当前阶段关联材料的摘录（每份最多 1500 字，总计 6000 字）。
- **导入**：先完整校验并规范化成新对象（重新生成项目、步骤、日志 ID），全部通过后才写入。
- **指标历史**：`project.metricHistory` 记录第 7、8 关每次关卡检查时的有效结果和所依据的修订，相同结果不重复记录；清空过期结果前也会记一笔。用于指标趋势卡片和报告中的趋势表。
- **批准人**：关卡放行、按规则通过、强制放行、补确认时记录 `approver` 与 `opinion`，写入日志、快照显示和决策报告；项目记住上次填写的批准人。

## 测试

- `node tests/engine.test.js`：推进引擎与规则的单元测试，包含两轮评审中每个反例。
- `python3 tests/browser_test.py`：浏览器端回归测试（37 项），直接打开 `public/index.html`，需要先安装 Playwright。

## 6. 界面布局

桌面端（宽度 ≥ 1081px）为一屏三栏：左侧竖向阶段进度、中间阶段内容、右侧决策台。页面本身不滚动，三栏各自在栏内滚动并隐藏滚动条。窄屏和手机上阶段进度改为横向，恢复整页滚动。

## 7. 已知限制

- 数据只存在当前浏览器里，换设备或清缓存会丢失（可导出 JSON 备份）。
- 演示模式的建议是规则模板，只覆盖常见情况。
- 没有登录和多人协作，这是需求阶段明确不做的范围。
