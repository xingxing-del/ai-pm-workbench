# 第二轮评审处理说明

第二轮评审复核了第一轮的修复，并提出 13 个新问题（N01–N13）。其中 3 个 P0 指出：即使所有推进都经过统一入口，也会因为"依据变了但旧状态没失效"而错误放行。本轮的做法是把"什么变化让什么失效"收成一张依赖关系表，所有修改走同一个变更入口。

| 编号 | 问题 | 处理 | 说明 |
|---|---|---|---|
| N01 | 关卡通过后修改依据，通过状态不撤销 | 已修复 | 任何修改后，已通过（非强制）的关卡按当前数据重新检查，不再满足就撤销，并连带撤销之后已通过的关卡。第 8 关新增"第 7 关仍然有效"。决策台提示无效的前置关卡 |
| N02 | 步骤层面的修改绕过版本机制 | 已修复 | 第 5、6 阶段的步骤增删、步骤产出修改、完成状态变化都会升对应修订；备注、风险标记、排序不升 |
| N03 | 会话过期只看规则结果，不看 AI 依据 | 已修复 | 会话同时保存规则结果签名和 AI 依据签名（相关阶段产出、步骤、关联材料、指标、修订号），任何一个变化都过期 |
| N04 | 实测值无效也能达标 | 已修复 | 实测值须为有效数字，单位为 % 时在 0 到 100 之间；样本量须为正整数；无效值显示"格式无效" |
| N05 | 快照不完整，修改前后值被截断 | 已修复 | 快照增加相关阶段产出（含错误样例）、结果所依据的修订、建议去向、未录入的指标；前后值保存全文，界面折叠 |
| N06 | 异常导入污染已有数据 | 已修复 | 先完整校验并规范化成新对象（重新生成所有 ID），通过后才写入 |
| N07 | "已核验"和"关卡已确认"没衔接 | 已修复 | 新增"检查并确认第 N 关"，不改变当前阶段；核验提示里说明还需要单独确认关卡 |
| N08 | 关联材料没有进入模型上下文 | 已修复 | 当前阶段关联材料的摘录发给模型（每份最多 1500 字，总计 6000 字） |
| N09 | 无实质变化也让结果过期 | 部分同意并修复 | 真实浏览器里同值不会触发 change 事件，但仍加了前后值比较；只改指标名称不再升标准修订 |
| N10 | 测试没覆盖交互路径 | 已修复 | 单元测试补上每个反例；新增 `tests/browser_test.py` 放进仓库 |
| N11 | 理由和版本解释偏重 | 已修复 | 理由默认显示前两句；"版本 v2"改称"构建修订 2"，说明它不是 Prompt 版本 |
| N12 | 模型超时只保护到响应头 | 已修复 | 超时覆盖请求和读取响应全过程 |
| N13 | 补充材料异步返回可能画到错误项目 | 已修复 | 返回时如果已切换项目，只保存不重绘 |
