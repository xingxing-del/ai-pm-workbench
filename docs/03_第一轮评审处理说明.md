# 第一轮评审处理说明

第一轮评审提出了 19 个问题。下表说明每条的处理方式。「已修复」表示按建议实现；「缩小范围」表示只做了一部分，原因写在说明里；「未做」表示有意不做。

| 编号 | 问题 | 处理 | 说明 |
|---|---|---|---|
| 01 | 检查后改数据，仍能用旧结果放行 | 已修复 | 打开关卡时记录规则结果签名；之后相关数据一改，会话标为过期，只能「重新检查」。拍板时再检查一次，签名不一致则拒绝 |
| 02 | 「问 AI 下一步」可绕过关卡 | 已修复 | 新增 `engine.js`，`Engine.advance()` 是唯一的前进函数：关键节点在调用时重新检查，不通过就拒绝（除非显式强制放行）；前进一次只能一步。所有按钮都走它 |
| 03 | 改标准或改构建后，旧通过状态和旧评测仍有效 | 已修复 | 项目有三个版本号：标准、评测集、构建。标准变化使第 3、7、8 关失效；评测集或构建变化使第 7、8 关失效。结果录入时记下所依据的版本，版本不一致即过期，输入框锁定，须清空重录。旧值写进日志 |
| 04 | 第 10 阶段两条回流路径行为不同 | 已修复 | 第 10 阶段的所有回流都调用 `Engine.backflow()`；没有失败案例时须写原因 |
| 05 | 定位太宽，竞品断言无依据 | 已修复 | README 改为一句话定位加一个具体冲突场景；竞品说法改为「有限范围的观察」；参考论文注明是预印本，并说明不能证明十阶段通用 |
| 06 | 只记录决定，没记录依据 | 已修复 | 每次决策保存快照：规则明细、指标实测与阈值、版本、关联材料、AI 完整建议，可从决策记录和日志打开。产出修改记录前后值 |
| 07 | 示例建议结论过强 | 已修复 | 示例数据补了分类型统计（示例值）；建议改为「优先验证某假设」并给出验证方法和两条备选路线；界面标注「预设演示建议」 |
| 08 | 第 3 关允许没有评测指标 | 已修复 | 第 3 关要求至少一个评测指标；校验名称、方向、阈值；单位为 % 时阈值在 0 到 100 之间 |
| 09 | 评测集完成可由全部跳过满足 | 已修复 | 第 7 关要求评测集说明和样本量；步骤检查会显示跳过了几个 |
| 10 | 第 8 关不看观测基础 | 缩小范围 | 只加了「灰度样本量」必填。统计口径、结果日期等未加：演示中价值有限，会增加填写负担 |
| 11 | 第 2 关「材料齐全」和「可以立项」混在一起 | 已修复 | 结论为「不可行」时规则拦截；新增「终止项目」（任意关卡可用，须写原因，可重新开启） |
| 12 | 按最靠后文件开始，不等于前置阶段有产出 | 已修复 | 改称「当前工作阶段」；之前的阶段标为「未核验」，须手动标记已核验 |
| 13 | 决定按钮被挤出首屏 | 已修复 | 决策栏吸附在右栏底部；打开关卡时收起「下一步」卡片；理由可折叠；中间栏加上下滚动阴影 |
| 14 | 确认页增删步骤丢失名称和起始阶段 | 已修复 | 重绘前统一同步名称、起始阶段和步骤 |
| 15 | 保存失败静默、缺恢复入口 | 已修复 | 保存失败提示；新增导出与导入（格式校验，同 ID 自动改名）。在 iframe 中打开时隐藏导出，因为下载无效 |
| 16 | 十阶段「通用」说法过强、并行和第 9 阶段出口 | 缩小范围 | 改称「默认流程」；第 9 阶段新增继续监控 / 发起迭代 / 结束项目；第 7 关同时检查第 5、6 阶段。没有改成多个「当前阶段」：状态逻辑会明显变复杂 |
| 17 | 「上传」与「手填」不一致 | 已修复 | 第 4 关改为「PRD 内容已记录，或已关联 PRD 材料」；新增每个阶段的「关联材料」；结果字段改名为「录入」。没有做 CSV 结果自动导入 |
| 18 | 解析依赖外网，截断后无标记 | 部分修复 | 解析组件加载加 15 秒超时和替代方案提示；超长文件在材料中标明「已截断，原文 N 字」。没有把组件随仓库离线打包：体积会明显变大 |
| 19 | 异步建议缺请求身份与超时 | 已修复 | 会话带请求 ID 和项目 ID，返回时不一致则丢弃；新建项目的分析带草稿令牌；前端加 60 秒超时 |
